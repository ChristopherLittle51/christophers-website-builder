# Developer-focused builder components

The **Developer** category adds twelve editable components that share the
builder's editorial typography, theme controls, responsive spacing, and
section-anchor behavior. They are presentation blocks: no credentials, private
runtime state, or client-side integration configuration is stored in them.

| Component | Use it for |
| --- | --- |
| Developer hero | A technical homepage introduction with availability status and CTA. |
| Code snippet | A named, language-labeled static code example. |
| Terminal session | A styled sequence of command, output, and success rows. |
| Tech stack | A concise list of technologies and their roles. |
| Developer features | A two- or three-column capability grid. |
| API endpoint | A documented HTTP method, path, response example, and auth note. |
| Architecture | A system boundary diagram with editable nodes and connections. |
| Changelog | Dated release entries with labels and details. |
| Open source | A repository-oriented project card with contribution CTA. |
| Developer stats | Metric cards for technical outcomes or operating facts. |
| Docs callout | A linked reference or implementation note. |
| Developer CTA | A technical close with primary and secondary links. |

All twelve blocks can also be placed inside any builder slot, including the
layout and new flex containers. The new components use semantic landmarks,
lists, headings, and code elements where they improve reading and assistive
technology support. Endpoint and code contents are rendered as text rather than
executed.
